**A message to a session on another device now arrives exactly like one from a session on this machine, and wakes it.** It lands as a message from another session (never as typed user input, never naming the device), is delivered once even when retried, and starts the receiving session's turn on its own; the receiver answers only if it chooses to, by sending a message back. A device whose engine cannot take such a message says so instead of receiving it as user input. ([#9999999](https://github.com/code-yeongyu/oh-my-openagent/pull/9999999), part of [#12879](https://github.com/code-yeongyu/oh-my-openagent/issues/12879))

## 2026-11-09 - A cross-device send is the same delivery as a same-device send (#9999999, part of #12879)

`thread/remote/relay-transport.ts` sends a peer session's message to another device as senpi#6233 `admit_external_message` built from the same delivery a local send makes: `gateway/envelope.ts` `senderFacts` (moved out of `engine.ts`) names the sender, `renderDeliveryText` renders the text (no device in it), `decideDelivery` decides a steer, the record carries the send's own `deliveryId` (the receiver dedupes it; `already_admitted` is reported `deduplicated: true`), an `agent` sender claim, `deliverAs` and `chainCount`. An engine that has no such record (`method_unclassified`, `delegation_unclassified`, `unknown_command`, ...) fails `unsupported` and is never sent a user prompt; `held_draft` answers `queued` and the same record is retried on a bounded backoff (`relay_delivery_held` / `relay_delivery_failed` log lines; timers cleared at shutdown through `GatewayServices.disposeTransports`). `remote/peer-text.ts` is deleted; `remote-ops.ts` `promptRemote` is now only a person's own prompt (`omo remote send`). The chain continues on both legs: `component.ts` keeps the run's `chainHop` from an admitted delivery's engine-stamped `chain_count` (a delivery from another device is no local `cause`), the relay leg sends `chainCount = hop`, and the local leg passes `inbound_hop` to `store-ops.ts`, which places the row at `max(cause hop, inbound hop) + 1`. The SDK send resolves other devices and refuses a command-line sender there (`unsupported`, `sender_not_allowed`) before any record.
